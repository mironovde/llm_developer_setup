# Task Decomposition — Декомпозиция задачи на подзадачи

TASK: Декомпозировать [$ARGUMENTS] чтобы получить атомарные, параллелизуемые подзадачи с чёткими критериями готовности.

## RULES
1. Каждая подзадача = 1 коммит, завершаема за 1-2 часа
2. Максимизируй параллельные задачи, минимизируй зависимости
3. Каждая подзадача имеет чёткий критерий готовности

## Процесс

### 1. Анализ задачи
- Определи конечную цель и критерии приёмки
- Определи ограничения (технические, временные, зависимости)
- Определи кто конечный пользователь результата

### 2. Разбивка по компонентам
- **Data/Models** — схемы, миграции, типы
- **Business Logic** — сервисы, утилиты, API
- **UI/Presentation** — компоненты, стили, UX
- **Integration** — связи между компонентами
- **Testing** — тесты для каждого компонента

### 3. Граф зависимостей
```
[Task A] --> [Task C] --> [Task E]
[Task B] --/           --> [Task F]
[Task D] (independent)
```

### 4. Создание задач
Используй TaskCreate для каждой подзадачи.
Установи зависимости через TaskUpdate с addBlockedBy/addBlocks.

### 5. Стратегия выполнения
- **Explore** — исследование
- **general-purpose** — реализация
- **Bash** — тесты/билды
- **Plan** — архитектура

## Паттерны

- **Feature**: research → data layer → business logic → UI → integration → tests
- **Bugfix**: reproduce → root cause → fix → regression test
- **Refactor**: understand → plan → incremental changes → verify

Выполни декомпозицию и создай задачи через TaskCreate.
