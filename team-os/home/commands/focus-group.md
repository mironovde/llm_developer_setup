# Focus Group — Исследование продукта через фокус-группы

Проведи фокус-группу: $ARGUMENTS

## Процесс

### Шаг 1: Владелец продукта (Product Owner agent)

Запусти агента-владельца продукта. Он:
1. Изучает текущий продукт (код, UI, CLAUDE.md, README, роуты, компоненты)
2. Определяет **ключевые потребности**, которые продукт решает (3-5 потребностей)
3. Группирует потребности в **фокус-группы** (1 группа = 1 потребность или кластер похожих)
4. Для каждой группы определяет **персоны** (3-5 человек с этой потребностью, разные демографии/контексты)

Формат выхода:
```
FOCUS GROUP PLAN
================
Продукт: [название]
Потребности: [список]

Группа 1: [потребность]
  Персоны: [имя — контекст, возраст, опыт, мотивация]

Группа 2: [потребность]
  Персоны: [...]
```

### Шаг 2: Проведение фокус-групп (ПОСЛЕДОВАТЕЛЬНО)

Для каждой группы **последовательно** (НЕ параллельно между группами):

1. Запусти агентов-участников **параллельно** (каждый агент = 1 персона)
2. Каждый агент-участник:
   - Принимает свою персону (имя, контекст, мотивация, уровень опыта)
   - Изучает продукт **глазами этой персоны** (UI, UX flow, код если релевантно)
   - Отвечает на вопросы:
     - Что понравилось? Что работает хорошо?
     - Что раздражает или непонятно?
     - Что мешает достичь цели?
     - Чего не хватает?
     - Как бы вы описали этот продукт другу?
   - Выдаёт **честную обратную связь** от лица персоны (НЕ комплименты, а реальные проблемы)

3. Агент-модератор собирает ответы группы, выделяет:
   - **Общие паттерны** (что отметили 2+ человека)
   - **Уникальные инсайты** (неожиданные наблюдения)
   - **Цитаты** (яркие формулировки от персон)

### Шаг 3: Синтез инсайтов (после ВСЕХ групп)

Владелец продукта анализирует результаты всех групп:

```
FOCUS GROUP INSIGHTS
====================

КРИТИЧЕСКИЕ ПРОБЛЕМЫ (блокируют цель пользователя):
1. [проблема] — отметили [N] из [M] участников
   Цитата: "[цитата от персоны]"

FRICTION POINTS (замедляют, но не блокируют):
1. [проблема]

MISSING FEATURES (чего не хватает):
1. [фича]

POSITIVE (что сохранить):
1. [что работает]

ПРИОРИТИЗАЦИЯ (по impact × frequency):
1. [проблема/фича] — Impact: HIGH, Frequency: 4/5
2. [проблема/фича] — Impact: HIGH, Frequency: 3/5
3. ...
```

### Шаг 4: Планирование и имплементация

НЕ спрашивай пользователя — сразу действуй:

1. Преврати приоритизированные инсайты в **конкретные задачи**
2. Запусти `/gsd:quick` или `/gsd:plan-phase` для имплементации
3. Имплементируй все задачи по приоритету
4. Верифицируй результат

## Правила

- **НЕ задавай вопросов** — фокус-группа сама генерирует ответы
- **Честность > вежливость** — агенты-участники должны быть критичными, не хвалить просто так
- **Несколько групп = последовательно** — сначала одна группа целиком, потом следующая
- **Внутри группы = параллельно** — все участники одной группы работают одновременно
- **После инсайтов = сразу имплементация** — не спрашивая подтверждения
- Количество групп: по умолчанию 2-3, больше если продукт сложный
- Участников в группе: 3-5 человек

## Примеры персон

| Тип | Пример |
|-----|--------|
| Новичок | "Мария, 28, впервые использует подобный продукт, не техническая" |
| Опытный | "Алексей, 35, использует аналоги 3+ года, высокие ожидания" |
| Power user | "Дмитрий, 42, разработчик, ищет API/автоматизацию" |
| Нетипичный | "Елена, 55, бухгалтер, слабое зрение, использует с телефона" |
| Скептик | "Игорь, 30, пришёл от конкурента, сравнивает всё" |

Персоны подбираются под конкретный продукт и его аудиторию.
