# Legal Compliance — Анализ и генерация правовых документов проекта

TASK: Проанализировать текущий проект и сгенерировать необходимые правовые документы [$ARGUMENTS] чтобы обеспечить юридическое соответствие перед деплоем.

SUCCESS BRIEF:
- Тип выхода: правовые документы в /legal/ + deployment checklist
- Успех = все необходимые документы созданы, плейсхолдеры перечислены, чеклист выведен

## Шаг 1: Анализ проекта

Просканируй кодовую базу для определения функциональности, требующей правовых документов.

### 1.1 Источники метаданных

Прочитай (если существуют):
- `package.json` / `composer.json` / `Gemfile` / `pyproject.toml` — название, описание, зависимости
- `CLAUDE.md` / `MEMORY.md` — описание проекта, стек, домен
- `.env.example` — используемые сервисы
- Конфиги деплоя: `vercel.json`, `Dockerfile`, `docker-compose.yml`, `netlify.toml`

### 1.2 Детекция функциональности

Используй Grep/Glob для поиска паттернов:

| Функциональность | Что искать | Документы |
|------------------|-----------|-----------|
| **Платежи** | `yookassa`, `stripe`, `storekit`, `paypal`, `tinkoff`, `robokassa`, `cloudpayments`, `sberbank`, `payment`, `billing`, `checkout` в коде и зависимостях | offer, refund-policy |
| **Авторизация / формы** | `auth`, `login`, `register`, `signup`, `sign-up`, `password`, `session`, `jwt`, `oauth`, `supabase/auth`, `firebase/auth`, `next-auth`, `passport` | privacy-policy, consent |
| **Персональные данные** | `email`, `phone`, `name`, `address`, `birthdate`, формы с input полями, модели User | privacy-policy, personal-data-processing |
| **Аналитика** | `gtag`, `GA-`, `G-`, `metrika`, `ym(`, `analytics`, `hotjar`, `mixpanel`, `amplitude`, `posthog`, `plausible` | cookie-policy, privacy-policy |
| **Cookies** | `cookie`, `localStorage`, `sessionStorage`, `setCookie`, `js-cookie`, `nookies` | cookie-policy |
| **UGC (пользовательский контент)** | `comment`, `review`, `upload`, `post`, `forum`, `chat`, `message`, модели Comment/Post/Review | user-agreement, content-moderation |
| **E-commerce** | `cart`, `order`, `product`, `catalog`, `shop`, `store`, `price`, `sku`, `inventory` | offer, refund-policy, delivery |
| **Подписки** | `subscription`, `plan`, `trial`, `recurring`, `billing_cycle` | offer, subscription-terms |
| **Рассылки** | `newsletter`, `mailing`, `mailchimp`, `sendgrid`, `unisender`, `resend`, `email-marketing` | privacy-policy, consent |

### 1.3 Определение юрисдикции

- Русскоязычный проект / домен .ru / YooKassa / Яндекс → **РФ** (152-ФЗ, ФЗ-54, закон о рекламе)
- Английский / Stripe / международный домен → **International** (GDPR + fallback)
- Оба → генерировать оба набора

На основе детекции определи необходимые документы:

## Шаг 3: Генерация документов

### 3.1 Проверка существующих

```bash
ls -la [project-root]/legal/ 2>/dev/null
```

**Важно**: НЕ перезаписывай существующие документы. Если документ уже есть:
1. Сравни с шаблоном — есть ли пропущенные секции
2. Предложи обновление, но НЕ перезаписывай
3. Пометь как `[EXISTS - review recommended]`

### 3.2 Копирование шаблонов

Для каждого нужного документа:

1. Проверь наличие шаблона в `~/.claude/legal-templates/`
2. Если шаблон есть — скопируй в `[project-root]/legal/`
3. Если шаблона нет — сгенерируй базовый документ с правильной структурой для определённой юрисдикции и сохрани в `[project-root]/legal/`

### 3.3 Адаптация к проекту

Заполни автоматически (из метаданных проекта):
- `{{PROJECT_NAME}}` — из package.json name / CLAUDE.md
- `{{PROJECT_URL}}` — из vercel.json, homepage, или конфига
- `{{PROJECT_DESCRIPTION}}` — из package.json description
- `{{CURRENT_DATE}}` — дата генерации
- `{{CONTACT_EMAIL}}` — из package.json author или .env

Оставь незаполненными и перечисли:
- `{{COMPANY_NAME}}` — юридическое название
- `{{COMPANY_INN}}` — ИНН (РФ)
- `{{COMPANY_OGRN}}` — ОГРН (РФ)
- `{{COMPANY_ADDRESS}}` — юридический адрес
- `{{COMPANY_EMAIL}}` — официальный email
- `{{COMPANY_PHONE}}` — телефон
- `{{DPO_EMAIL}}` — email ответственного за обработку ПД
- `{{HOSTING_PROVIDER}}` — хостинг-провайдер
- `{{DATA_STORAGE_LOCATION}}` — место хранения данных
- Любые другие `{{...}}` плейсхолдеры

## Шаг 4: Deployment Checklist

После генерации документов ОБЯЗАТЕЛЬНО выведи чеклист:

```
LEGAL COMPLIANCE CHECKLIST
==========================

Документы: [список созданных]
Юрисдикция: [РФ / International / Both]

ПЕРЕД ДЕПЛОЕМ:
--------------
[ ] Заполнить ВСЕ плейсхолдеры {{...}} в документах:
    [перечислить конкретные плейсхолдеры и в каких файлах]

[ ] Добавить ссылки в footer сайта:
    - Политика конфиденциальности → /legal/privacy-policy
    - Пользовательское соглашение → /legal/user-agreement
    - [другие документы]

[ ] Cookie consent banner:
    - Показывать при первом визите
    - Кнопки: "Принять" / "Настроить" / "Отклонить"
    - Не загружать аналитику до согласия
    - Сохранять выбор пользователя

[ ] Формы — чекбоксы согласия:
    - Регистрация: "Согласен с Пользовательским соглашением и Политикой конфиденциальности"
    - Оформление заказа: "Согласен с условиями Оферты"
    - Подписка на рассылку: "Согласен на получение рекламных материалов"
    - Чекбокс НЕ может быть предзаполнен (GDPR / 152-ФЗ)

[ ] Техническое:
    - Логировать факт согласия (timestamp, IP, версия документа)
    - Версионировать документы (дата последнего обновления)
    - Обеспечить возможность отзыва согласия

[ ] Проверить с юристом (рекомендация):
    - Документы сгенерированы AI и требуют юридической проверки
    - Особенно: оферта, политика возвратов, обработка ПД

ПРЕДУПРЕЖДЕНИЯ:
--------------
[список критических замечаний если есть]
```

## Шаг 5: Deploy Hook Reminder

**При обнаружении команд деплоя** (`vercel deploy`, `npm run build`, `npm run deploy`, `docker build`, `docker-compose up`, `netlify deploy`, `fly deploy`, `railway up`):

1. Проверь `[project-root]/legal/` на наличие незаполненных `{{...}}`
2. Если найдены — ПРЕДУПРЕДИ:

```
⚠ LEGAL COMPLIANCE WARNING
============================
Обнаружены незаполненные плейсхолдеры в правовых документах:

[файл]: {{PLACEHOLDER_1}}, {{PLACEHOLDER_2}}
[файл]: {{PLACEHOLDER_3}}

Деплой с незаполненными документами может привести к юридическим рискам.
Заполните плейсхолдеры или подтвердите деплой без них.
```

3. Если `/legal/` не существует — напомни о необходимости запустить `/legal-compliance`

### `placeholders` — показать все незаполненные плейсхолдеры
