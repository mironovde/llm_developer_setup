# Context Manager — Оптимизация контекста сессии

Действие: $ARGUMENTS

## Auto-detection (без аргументов)

Если `$ARGUMENTS` пустой — определи нужное действие автоматически:
1. Проверь длительность сессии (> 30 мин → `optimize`)
2. Проверь количество завершённых задач (3+ → `status`)
3. Проверь "Last verified" в MEMORY.md (> 14 дней → `freshness`)
4. По умолчанию → `status`

## Операции

### `status` — Состояние сессии
- Сколько файлов прочитано?
- Сколько задач в работе?
- Нерелевантный контекст?
- Здоровье: Optimal / Heavy / Critical
- Рекомендация: continue / optimize / cleanup

### `cleanup` — Очистка
- Что выгрузить
- Сводка завершённой работы
- Рекомендации

### `optimize` — Оптимизация
- Консолидация информации
- Приоритизация по релевантности
- Сохранение обнаруженных паттернов в MEMORY.md
- Обновление "Last verified" даты

### `freshness` — Проверка актуальности

Сканируй MEMORY.md и CLAUDE.md текущего проекта:

1. **Даты**: "Last verified" > 14 дней → пометить stale
2. **Пути**: проверь существование ключевых файлов из memory
3. **Расхождения**: сравни memory с реальным состоянием проекта (stack, structure)
4. **Stack**: проверь package.json / requirements.txt vs записи в memory

Выведи:
```
FRESHNESS REPORT
================
Project: [name]
Last verified: [date] → [FRESH / STALE]

Paths checked: [N]
  ✓ [path] — exists
  ✗ [path] — MISSING (remove from memory)

Stack: [MATCH / DRIFT]
  [расхождения если есть]

Recommendations:
- [что обновить]
```

Обнови "Last verified" дату после проверки.

## Категории контекста

| Категория | Правило |
|-----------|---------|
| Активный (текущая задача) | Держать |
| Справочный (доки) | По требованию |
| Архивный (завершённое) | Выгружать |

## Триггеры
- Сессия > 30 минут
- Несколько завершённых задач
- Переключение кодовых баз
- Медленные ответы

Выполни запрошенное действие.
