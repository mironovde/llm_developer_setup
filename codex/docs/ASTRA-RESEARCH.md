# GPT-6 Astra: основания настройки

Проверено 6 сентября 2026. Источники прочитаны в интернете; локальная проверка —
Codex CLI 0.152.0 и каталог установленной модели. Решения ниже — настройка под
запрос владельца, а не универсальные требования OpenAI.

## Официальные источники

1. [Гайд GPT-6 Astra](https://developers.openai.com/api/docs/guides/latest-model).
   Модель чувствительна к инструкциям skills/AGENTS; полезны явное доведение
   поручения до результата, понятные условия вопросов и соразмерные проверки.
   Гайд рекомендует при миграции сохранять текущий effective reasoning effort.
2. [Карточка Astra](https://developers.openai.com/api/docs/models/gpt-6-astra).
   API-контекст 1 050 000 токенов не определяет рабочий бюджет конкретного Codex.
3. [Загрузка AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
   Глобальный файл наследуется проектами. Локальные инструкции уточняют его;
   `AGENTS.override.md` имеет приоритет. Новая сессия перечитывает файлы.
4. [Справочник конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference)
   и [профили](https://learn.chatgpt.com/docs/config-file/config-advanced).
   Параметры модели задаются в TOML. Актуальный профиль — отдельный
   `~/.codex/<name>.config.toml`, выбираемый через `--profile`.

## Локальные факты и решения

| Наблюдение | Решение |
| --- | --- |
| В репозитории `gpt-5.6-terra/medium`; live — `gpt-6-astra/xhigh` | Согласовать модель. Для запрошенной экономии попробовать `medium`, каталог Codex также называет его значением по умолчанию. `xhigh` оставить профилем `astra-deep`. Это осознанный эксперимент сверх консервативного совета миграции; ускорение не измерено. |
| Live вручную задаёт `model_context_window = 1050000`; каталог: рабочее окно 272000, максимум 872000 | Удалить ручное значение. Не подменять динамический каталог API-параметрами и не задавать искусственный порог compaction. |
| Краткое глобальное соглашение не определяет доставку | Добавить цель, ID, критерии, зависимости, точки сверки и Git-порядок. |
| `~/AGENTS.md` содержит старые обязательные skills, чужие API и церемонии | Заменить короткой заметкой: глобальные правила находятся в `~/.codex/AGENTS.md`. Этот файл не является глобальным автоматически и обычно не входит в цепочку Git-проекта. |
| Корневой CRM AGENTS дублирует руководство REPL и навязывает GSD | Оставить факты проекта, существующую `.planning/`, команды и реальные ограничения. Не дублировать документацию инструментов. |
| Delo Yasno 3 уже имеет полезные ограничения доставки, Browser/Excel и ресурсов | Сохранить специфичные требования; общую процедуру перенести в глобальное соглашение. |
| Установлены разнообразные skills и MCP | Сохранить подключения. Выбирать релевантные инструменты по цели, не запускать весь каталог. Пакетные файлы плагинов не редактировать: обновление их перезапишет. |

## Проверяемая модель работы

Нумерация, частота push, одна активная поставка и критерии завершения — требования
владельца. По умолчанию `D001`, `D001-T01`, ветка `codex/001-<смысл>`; существующие
ID и workflow проекта имеют приоритет. Небольшая правка не требует нового roadmap.

Автономность означает самостоятельные действия внутри поручения и остановку
расширения объёма после достижения цели. Каждая законченная часть проверяется,
коммитится и отправляется в рабочую ветку; публикация не откладывается до большого
релиза. Merge/deploy следуют существующим полномочиям проекта.

Прозрачность обеспечивают сообщения в чате, журнал фактов и ссылки на Git.
Показ скрытого рассуждения не нужен. Правила не являются техническим watchdog:
их соблюдение проверяется на реальных задачах, а не обещается установщиком.

## Приёмка эффективности

На ближайших сопоставимых задачах записывать: достигнутые критерии, длительность,
токены если доступны, число существенных повторных проверок/лишних UI-вызовов,
своевременность push и понятность прогресса. Минимум: документационная правка,
баг с регрессией, UI-сценарий и продолжение после смены сессии. Если `medium`
теряет качество, использовать `high`/`astra-deep` и сравнить фактические результаты.
Изменение effort в файле не переключает уже работающую задачу.
